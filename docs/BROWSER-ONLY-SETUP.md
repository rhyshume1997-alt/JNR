## 2. Create the first administrator (no scripts, password never in chat)
Chosen because it adds **no new server route**: a one-time route would need a bootstrap token and a public sign-up endpoint. Instead a static page hashes the password inside Rhys's own browser tab (PBKDF2, 600,000 rounds), makes no network request, and gives SQL that holds only the salted hash. The server accepts that hash and replaces it with its stronger scrypt hash at the first sign-in. The SQL only creates a user if there are no users yet, so pasting it twice or later does nothing.
5. **[RHYS]** In a browser signed in to Vercel, open `https://jnr-git-feature-workshop-content-rhsys-projects.vercel.app/admin/first-admin` (wait for the latest preview to finish building).
6. **[RHYS types, Claude must not read or type this]** Email, name, a password of 14+ characters (a few random words), the same password again. Press **Make the SQL**. The password boxes clear themselves.
7. **[CLAUDE]** Press **Copy SQL** (the page never needs to be read), open the Neon SQL editor, paste, **Run**. Expect `INSERT 0 1`.
8. **[RHYS]** Open `/admin` on the preview and sign in with the email and password just chosen. Done. Close the first-admin page.
Note: Neon keeps a query history containing the salted hash (not the password). You can delete that history entry. **Before any merge** this page (`admin/first-admin.html`, `assets/first-admin.js`, `assets/pbkdf2-hash.js`) is removed from the branch, and `npm run premerge:check` fails until it is. Tell Claude Code as soon as the admin can sign in so it can remove the page (that makes a new commit, so a new reviewed SHA).

## 3. Run staging:check and staging:e2e from GitHub, safely
A GitHub Action (`.github/workflows/staging-checks.yml`) runs the same scripts. **Cost: none** (the repo is public, so standard runners are free; a run takes 1 to 3 minutes).
**How the credentials are protected** (reviewed; see `docs/SECURITY-REVIEW.md`): the credentials live only in a `staging` environment that accepts runs **only from tags named `staging-*`**, never from a branch, so pushing a changed workflow or script to `feature/workshop-content` cannot reach them. Only Rhys can create those tags. A tag points at one exact commit and that commit's code is what runs. The job stops unless that commit equals the `APPROVED_SHA` Rhys stored in the environment, and Rhys must approve every run. Each mode gets only the credentials it needs.
9. **[RHYS]** Settings > Rules > Rulesets > **New ruleset** > **New tag ruleset**. Name `staging tags`. Enforcement **Active**. Bypass list: add the role **Repository admin**. Target tags: **Include by pattern** `staging-*`. Rules: tick **Restrict creations**, **Restrict updates**, **Restrict deletions**. Create. (Now only Rhys can create these tags; Claude's access cannot.)
10. **[CLAUDE Code, after step 9]** Asks to run the **ruleset probe**: it tries to push a tag `staging-ruleset-probe` and must be **refused**. If it is not refused, stop: the ruleset is wrong. (The probe name matches none of the workflow's triggers, so it cannot start a run.)
11. **[RHYS]** Settings > Environments > **New environment** `staging`. Tick **Required reviewers** and add Rhys (untick "Prevent self-review" if shown). Under **Deployment branches and tags** choose **Selected branches and tags** > **Add deployment branch or tag rule** > Ref type **Tag** > pattern `staging-*`. **Do not add any branch rule.**
12. **[RHYS pastes; CLAUDE can navigate]** In that environment (not "Repository secrets") add **Environment secrets**: `DATABASE_URL` (Neon **pooled** string, Neon > Connect), `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, and later `BUFFER_API_TOKEN`. There must be **no repository-level secrets**.
13. **[CLAUDE]** Same page, **Environment variables**: `S3_BUCKET_PRIVATE=jnr-staging-private`, `S3_BUCKET_PUBLIC=jnr-staging-public`, `PUBLIC_MEDIA_BASE_URL` (the `pub-….r2.dev` address), `BUFFER_STAGING_CHANNEL_ID=6afa05fbece6dfde5fd74165`, `STAGING_ORIGIN=https://jnr-git-feature-workshop-content-rhsys-projects.vercel.app`.

To run a check, **[RHYS]** creates a tag at the approved commit: repo > Releases > **Draft a new release** > Choose a tag > type `staging-<mode>-<first 7 characters of the SHA>` (for example `staging-services-4373cab`) > **Create new tag on publish** > Target: pick the approved commit under Recent commits > tick **Set as a pre-release** > **Publish release**.
